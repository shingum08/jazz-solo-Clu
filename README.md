# 재즈 즉흥 악보 생성기 (Jazz Solo Generator)

**▶ 데모: https://shingum08.github.io/jazz-solo-generator/**

코드 진행을 고르면 **매번 새로운** 연습용 즉흥 솔로 악보를 만들어 주고, 반주와 함께 들려 주는 단일 HTML 웹앱.
규칙 기반 엔진이 **Weimar Jazz Database 실측 통계**를 확률로 사용해 "사람 같은" 라인을 만든다.

수정 작업 버전 **v0.54.0 "Clu"**. 배포 여부와 검증 결과는 별도로 확인해야 한다. 버전 이력 전체는 [CHANGELOG.md](CHANGELOG.md), 되돌릴 수 있는 시점은 [CHECKPOINTS.md](CHECKPOINTS.md)에 있다 — 이 README에는 현재 기능 요약만 둔다.

> 마스터 기획안: [docs/blueprint-v1.0.pdf](docs/blueprint-v1.0.pdf) — 프로젝트 전체 로드맵(v1~v4), ML·RAG 확장 설계, 비용·법무 프레임.

## 엔진 — 한 소절이 만들어지는 6단계

v0.11까지는 "지금 이 코드에 어울리는 음"을 한 음씩 골랐다. 이 방식에는 라인에 방향이 생기지 않는다.
실제 연주자의 사고 순서인 **"다음 코드의 어디에 도착할지 먼저 정하고, 거기로 걸어간다"**를 그대로 구현했다.

1. **화성 분석** — 코드의 기능을 읽는다. D7→Gm은 "단조로 가는 Ⅴ"(♭9·♭13), G♭7→F는 트라이톤 대리(리디안 ♭7), Ⅳ 자리 maj7은 리디안, 토닉 마이너는 멜로딕 마이너.
2. **프레이즈·쉼 계획** — 연주자별 실측 프레이즈 길이·쉼 길이 분포로 호흡을 정하고, 형식 경계 직전에 종지를 맞춘다.
3. **리듬** — 박 단위 마르코프 체인. WJD 전사에서 잰 "이 박에서 다음 박으로 어떤 리듬이 오나" 확률. 마디선을 넘는 붙임줄 당김음이 자연스럽게 생긴다.
4. **타깃음** — 코드가 바뀌는 다운비트에 가이드톤(3음·7음)을 먼저 정하고, 직전 음과 반음·온음이면 가중치를 높여 보이스리딩을 이어지게 한다.
5. **어프로치 역산** — 타깃 앞 1~2음을 반음 어프로치·스케일 어프로치·인클로저로 채운다. 크로매틱음은 약박 반음 진행으로만 쓴다.
6. **어휘 셀** — 남은 자리는 프로필의 코드 대비 음 분포·음정 분포로 채우고, WJD에서 4명 이상 연주자가 공통으로 쓴 4~5음 셀 134종을 음형 그대로 넣는다.

프레이즈 단위로는 **연습 주제**(한 프레이즈를 한 소재로만)와 활용 스케일 변형이 붙는다.

## 한계 (알고 있는 것들)

- 모티프의 음정적 발전·시퀀스는 미완성. 코러스 곡선은 확률적 유도이며 개별 출력의 단조 상승을 보장하지 않는다.
- 곡 유형 태그는 보수적 규칙·명시 목록으로 추정한다. 모든 곡을 분석한 정답 레이블은 아니며 코르트레인 체인지 전용 어법은 미구현이다.
- 리듬 템플릿은 직접 작성한 패턴이다. WJD에서 추출한 프레이즈 템플릿으로 주장하지 않는다.
- MusicXML의 구조 회귀 검사와 실제 악보 프로그램·청취 검증은 다르다. 후자는 별도 검토가 필요하다.
- MIDI 파일 내보내기는 로드맵(MusicXML은 지원)

## 실행

빌드로 만들어진 결과물 하나(`index.html`)로 완결된 앱이다. 파일을 브라우저로 열면 끝난다.

```bash
# 방법 1: 그냥 열기
open index.html            # macOS (Windows: start index.html)

# 방법 2: 로컬 서버 (권장)
python3 -m http.server 8000
# → http://localhost:8000
```

## 개발 워크플로

```bash
# 1. 엔진 수정 (engine/engine_core.js, engine/playback.js) 또는 앱 수정 (app/template.html)
# 2. 앱 다시 빌드
python3 tools/build.py
# 3. 전수 테스트
node tools/test.js
# 4. 신기능 회귀 테스트
node tools/test_engine_v027.js
node tools/test_drill_v029.js
node tools/test_musicxml.js
# 5. index.html은 빌드 결과를 함께 커밋 (CI는 아직 미등록)
```

CI는 아직 원격에 등록되지 않았다. 현재 세션의 인증 권한으로 워크플로 업로드가 거부되었으므로 자동 실행을 주장하지 않는다. 전달 ZIP에 파일이 실제 포함됐는지도 별도로 확인한다. 기존 `test.js`는 엔진 불변식 검사이며, v0.27 기능은 `test_engine_v027.js`, `test_drill_v029.js`, `test_musicxml.js`로 따로 검사한다.

원칙: **엔진/프레젠테이션 분리**, **시드 기반 재현**(같은 시드 → 같은 악보). 이 원칙은 v1 이후에도 유지한다.
