# v0.61 외부 AI 검토 대조표 (2026-11-13)

v0.59.0 웹 빌드를 Gemini · GPT · Genspark에 보여 주고 받은 검토를 실제 코드와 맞춰 본 결과다.
판정: **맞음**(코드로 확인) · **일부 맞음** · **틀림** · **확인 필요**(이 작업에서 확인하지 못함).
GPT 설계서(「v0.60 설계·인수인계서」) 15번 항목의 1~5단계(소스 구조 확인 · 설계서와 차이 · 함수 계약 · 잠재 버그 · 기준 시험)를 이 문서로 갈음한다.

## 1. 실제 소스 구조 (설계서 가정과 다른 점)

| 설계서 가정 | 실제 | 영향 |
|---|---|---|
| `src/harmony/…` 같은 ES 모듈 구조, `export` | 단일 HTML 빌드. `engine/*.js`를 `tools/build.py`가 `app/template.html`에 끼워 넣음. 모듈 문법 없음 | 새 모듈도 `engine/*.js` 전역 함수 + 빌드 주입으로 만든다. `src/` 트리를 새로 만들지 않는다 |
| `planCTPath()`·`planSong()`·`tryMotif()`·`planApproach()`가 독립 함수 | 모두 `generateSolo()` **안쪽 클로저**(events·segs·rng를 공유) | 바깥에서 따로 부르거나 갈아 끼우기 어렵다. 어댑터보다 「옵션으로 켜는 가중치·규칙」이 현실적 |
| 음표 이벤트 `{startBeat, durationBeats, velocity, articulation, role}` | 틱 격자 `{t, d, midi, trip, tie, ph, strong, …}` — 1틱 = 8분 셋잇단의 1/2(8분 = 3틱, 마디 = 24틱). 세기는 재생 단계(playback.js)에서 정함 | 설계서 스키마로 바꾸지 않는다(AGENTS.md 원칙 3). 필요하면 읽기 전용 변환기만 |
| 화성 결과 `HarmonyContext{function, resolutionType, confidence…}` | `analyzeHarmony()` 구간마다 `{bar,t0,root,type,cls,scale,fn,tens,sname,ct,guide,label}`. 앞뒤 구간은 곡을 한 바퀴로 보고 이어 봄(마지막 코드의 다음 = 첫 코드) | `fn`(기능)·`guide`(가이드톤)는 이미 있다. 없는 것: 해결 유형·확신도·앞뒤 2~4마디 문맥 |
| 후보 여러 개를 만들어 점수로 고르기 | 고정 마디(locks)에만 6개 중 이음매가 가장 매끄러운 것 고르기가 있음 | 솔로 전체 후보 평가는 없음 — 새로 만들 수 있다(엔진 바깥 래퍼라 원칙을 안 깬다) |
| 회귀 시험을 새로 | `tools/test*.js·.mjs` 19종(이번 2종 포함) + `node tools/test.js`(264곡 × 3 × 3 × 2 = 4,752 솔로) | 이미 있음. 이번에 `test_levels_v061.js`·`test_meter_v061.js` 추가 |

## 2. Genspark 검토 대조

| # | 지적 | 판정 | 근거 · 이번 처리 |
|---|---|---|---|
| 1 | 4분음표마다 강박(`t%6===0`) — 2·4박도 코드톤 강제라 네모난 라인 | **맞음(설계 선택)** | 코드가 그렇다. 다만 「박마다 코드톤」은 비밥 교습(비밥 스케일)의 기본 원리이고 완료 정의의 「강박 코드톤 ≥80%」도 이것을 잰다. 단계 4·5에서 2·4박 경과음을 허용하는 옵션으로 실험할 가치 있음 — 결정 필요 |
| 2 | 다이내믹·아티큘레이션이 아예 없음 | **틀림(재생) / 맞음(악보)** | 재생(`playback.js` 106~110행)에 엇박 강조 0.95·마디 첫 음 0.9·하행 고스트 0.62·프레이즈 첫 음 강조가 있다. 악보(ABC)에 악센트·스타카토 기호가 없는 것은 맞음 |
| 3 | 스케일 변형이 사실상 고정(`phVar`가 「활용 스케일」 주제에서만 바뀜) | **맞음** | 단, Ⅴ→단조 얼터드(하모닉 마이너 5모드)·Ⅳ 리디안·트라이톤 대리는 자동. 코러스 곡선에 묶어 변형을 고르는 개선 후보 |
| 4 | 모티프 발전이 형식과 무관하게 확률로만 | **일부 맞음** | `roles`(진술·대조·해결)·코러스 곡선·쉬어 가는 섹션은 있으나 모티프 종류 선택이 역할과 연결되지 않음 |
| 5 | DP 플래너가 실측 음도·음정 분포를 안 씀 | **확인 필요** | 비용식 위치는 맞게 짚었으나 효과는 들어 봐야 함 |
| 6 | 16분음표를 표현할 수 없음 | **맞음** | 1틱 = 8분 셋잇단의 1/2이라 16분(1.5틱)이 없다. AGENTS.md 원칙 3(틱 격자) 변경이 필요한 큰 공사 — 별도 결정 |

## 3. Gemini 검토

전반적 방향(전조 감지·텐션 확장·가이드톤·어프로치·코러스 빌드업·콜 앤 리스펀스·스타일별 차이)은 맞지만 대부분 이미 있다:
가이드톤 경로·인클로저·반음 어프로치·코러스 곡선(ARC)·쉬어 가는 섹션·스타일 프로필·Ⅴ→단조 얼터드.
새로 쓸 만한 것: **전조(키 센터) 감지**(지금은 곡 전체 한 조 + 국소 Ⅱ-Ⅴ 판정), 스타일별 리듬(발라드·보사노바).

## 4. GPT 설계서

- 원칙(기존 보존·병렬 모듈·A/B·청취 평가·저작권)은 프로젝트 원칙과 같아서 따른다.
- 다만 `src/` 모듈 트리·이벤트 스키마 교체·모든 생성을 후보 3개 평가로 바꾸기는 단일 HTML 구조·틱 격자 원칙과 맞지 않아 **그대로 옮기지 않는다**.
- 현실적인 첫 단계: `engine/harmony_v2.js`(전역 함수)로 앞뒤 2~4마디 문맥(기능·해결 유형·확신도·가이드톤 경로)을 만들고, 기존 `analyzeHarmony()`와 **나란히 비교하는 시험**부터. 엔진에는 옵션으로만 연결.

5. 단계 4·5의 2·4박 경과음 허용(Genspark 1) — 듣고 결정
6. 16분음표 격자(Genspark 6) — 원칙 변경이라 별도 결정
