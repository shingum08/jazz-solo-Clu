# EzImprovJazz — 외부 자문용 현황 정리 (v0.65.0, 2026-11-14)

> 이 문서는 다른 AI(또는 전문가)에게 그대로 붙여 넣어 자문을 받기 위한 요약입니다.
> 맨 끝 「9. 묻고 싶은 것」이 핵심 질문입니다. 확인하지 못한 내용은 **(확인 필요)** 로 표시했습니다.

---

## 1. 무엇을 만드는가

- **EzImprovJazz** — 재즈 즉흥연주를 연습하는 (주로 관악기) 연주자를 위한 **연습용 솔로 악보 생성기**. 웹: ezimprovjazz.com (베타, 무료, 검색엔진 차단 중).
- 사용 흐름: 곡(코드 진행) 고르기 → 단계·연습 주제 고르기 → 솔로 악보 생성 → 베이스·피아노 반주와 함께 재생 → 좋은 마디는 남기고 나머지만 다시 생성.
- 만든 사람: 기획·청취 평가는 운영자(재즈 연주자) 1명, 코드는 AI(Claude)가 작성. 외부 테스터 규모 (확인 필요).
- 목표: 「이론적으로 맞는 음의 나열」이 아니라 **실제 연주자가 하는 것처럼 자연스럽고, 주제를 세우고 발전시켜 쌓아 올리는 솔로**.

## 2. 기술 구조

| 층 | 내용 |
|---|---|
| 형태 | 단일 HTML 파일 웹앱(빌드 스크립트가 엔진 JS를 끼워 넣음). 홈페이지(/) + 앱(/app/). Cloudflare Pages 정적 배포 |
| 생성 엔진 | **규칙 기반 + 실측 확률**. 무작위는 모두 시드 난수(mulberry32) — 같은 시드·설정이면 같은 악보 |
| 데이터 | **Weimar Jazz Database(WJD, ODbL 1.0)** — 솔로 전사 456개·약 20만 음 중 통계만 사용: 음도 분포·음정 분포·리듬 전이표·프레이즈 길이/쉼 분포·4명 이상이 함께 쓴 짧은 셀 157개. 연주자 계열 프로필 9종(전체·Parker·Clifford Brown·Rollins·Dexter Gordon·Chet Baker·Getz·Miles·Lester Young 계열) |
| 시간 격자 | 1틱 = 8분 셋잇단의 1/2 → 8분 = 3틱, 4분 = 6틱, 마디(4/4) = 24틱. **16분음표는 표현 불가**(1.5틱) |
| 곡 | 코드 진행만(원곡 멜로디·녹음 전사 없음). 앱 빌드 264곡, 웹 공개판은 연습 진행·공통 형식·퍼블릭 도메인 곡만. 사용자가 **iReal Pro 포럼 링크·MusicXML로 곡을 불러옴** |
| 출력 | ABC 기보 → abcjs로 악보, Web Audio로 재생(악기 샘플·스윙 비율·셈여림 강조) |
| 운영 | 마디 평가(👍👎) 익명 수집(Cloudflare Worker + D1 → 비공개 GitHub), 계정(Supabase, `?beta=1`로만 가입 — 이메일 인증 끔) |

### 생성 파이프라인(요약)
1. **화성 분석** — 코드마다 기능·스케일·가이드톤(3·7음)·텐션. Ⅴ→단조는 하모닉 마이너 5모드, 트라이톤 대리, Ⅳ 리디안 등.
2. **프레이즈 계획** — WJD 프레이즈 길이·쉼 분포 + 코러스 곡선(첫 코러스 성기게 → 빌드업 → 둘째 코러스부터 화려하게).
3. **리듬** — 박마다 토큰(4분·8분·당김·셋잇단·2박 셋잇단 등)을 WJD 전이표로. 장르별(라틴·보사노바·펑크·셔플·발라드) 리듬 묶음과 리프 반복.
4. **음 선택** — 강박(박마다) 코드톤 우선, 실측 음도·음정 분포, 코드톤 라인 DP, 어프로치·인클로저, 셀, 릭 사전, 하이라이트 장치(8분 라인·한 음 리듬 반복·피벗·헤미올라·어퍼 스트럭처·셋잇단 런), 모티프 발전, 스케일 색(리디안 ♭7·얼터드).
5. **검증** — 마디 합·음역·도약·셋잇단 묶음·겹침 전수 시험(264곡 × 3난이도 × 3악기 × 2시드 = 4,752 솔로, 위반 0).

### 사용자 옵션
- **난이도 5단계**: 1 입문 · 2 초급 · 3 중급(2박 셋잇단) · 4 중상급 · 5 심화(8분 셋잇단). 셋잇단은 연달아 2묶음까지.
- **연습 주제**: 자유 · 코드톤 라인 · 가이드톤 라인 · 펜타토닉 · 기본/활용 스케일. 「연습」 보기(드릴 음형).
- 노래↔비밥 조절바, 연주자 계열 스타일, 반주 6종, 악기 조(C·B♭·E♭), 코러스 1~12, 구간 반복, 마디 고르기·고정·다시 생성.

## 7. 남은 문제·한계

1. **장르 자연스러움** — 리듬 통계가 스윙 재즈(WJD)에서 와서 발라드·라틴/칼립소·펑크에서 어색함. 장르별 실측 리듬·프레이징 데이터가 없음.
2. **16분음표 없음** — 발라드 더블타임 런, 펑크 16분 싱코페이션, 비밥 빠른 런 불가.
3. **악보 아티큘레이션**(악센트·스타카토·고스트·스쿱) 미표기.
4. **화성** — 슬래시 코드 베이스 버림, `+`(증화음) 처리 근사, Harmony V2가 아직 생성에 안 쓰임.
5. **선율 어휘** — 사이드 슬리핑(아웃), 디지털 패턴(1-2-3-5), 트라이어드 페어, 비밥 스케일 정렬 미구현.
6. **평가 체계** — 자동 지표만 있고 「좋은 솔로」를 판정할 기준·청취 평가 절차가 없음.
7. **2·4박 경과음 허용 여부**(박마다 코드톤 원칙을 단계별로 완화할지).
8. **법·운영** — 개인정보처리방침·약관 미게시(회원가입 막아 둠), 연주자 실명 스타일 표기 검토, 요금제 미정(무료 베타).

## 8. 지켜야 할 제약

- 원곡 멜로디·특정 녹음 전사는 넣지 않음. 곡은 코드 진행만.
- WJD 파생물은 「확률 분포 + 4명 이상 공통 셀」까지(ODbL 1.0 출처 표기).
- 엔진은 브라우저 의존 없이 Node에서 돌아야 함, 시드 재현성 유지, 단일 HTML 배포.
- 사용자 대상 문구는 한국어.

## 9. 묻고 싶은 것

**A. 데이터·소스(라이선스가 맞는 것으로)**
1. 발라드·보사노바·라틴/칼립소·펑크 **솔로의 리듬·프레이징 통계**를 얻을 수 있는 공개 데이터셋이나 연구가 있는가? (라이선스·출처 포함)
2. WJD 말고 쓸 수 있는 **재즈 솔로 전사 코퍼스**(상업적 서비스에서 통계 파생 사용 가능)가 있는가?
3. 재즈 교육에서 쓰는 **어휘 분류 체계**(인클로저 종류, 비밥 스케일 규칙, 디지털 패턴, 트라이어드 페어, 아웃 기법)의 체계적 정리 자료.
4. 재즈 솔로의 **모티프 발전·프레이즈 구조**(질문-대답, 빌드업, 클라이맥스 배치)를 다룬 연구·교재.

**B. 방법**
5. 규칙 엔진 결과를 사람이 듣지 않고도 어느 정도 걸러낼 **평가 지표**(선율 자연스러움·그루브·발전성)와, 소규모 **청취 평가** 설계 방법.
6. 16분음표 지원을 위한 **시간 격자 확장**을 기존 틱 체계(8분=3틱)와 호환되게 하는 방법(예: 틱 2배).
7. 박마다 코드톤 원칙을 유지하면서 2·4박 경과음을 자연스럽게 허용하는 **비밥 스케일 정렬** 같은 규칙의 구체적 형태.
8. 발라드에서 「긴 음 + 짧은 장식 런」 대비를 규칙으로 만드는 방법, 칼립소(St. Thomas)·펑크 솔로의 전형적 리듬 셀.

**C. 제품·법**
9. iReal Pro 포럼 코드 차트를 사용자가 불러오게 하는 기능의 이용 조건상 주의점.
10. 「Charlie Parker 계열」처럼 연주자 이름을 스타일 이름에 쓰는 것의 위험과 대안 표기.
11. 비슷한 연습 앱·서비스(iReal Pro 등 — 경쟁 서비스 목록 자체도 조사 부탁)와 비교한 가격 정책 조언. 현재는 무료 베타, 요금제는 미정.
